# Execution model decision for #8

**Status: proposed by the coding agent for maintainer review. No production architecture or behavior change approved.** The maintainer endorsed the spike direction and authorized bounded tests. That is evidence to inform this decision, not approval of implementation. See [design and validation gates](design.md).

| Candidate | Evidence and consequence |
| --- | --- |
| Ordinary threads | [#9 report](https://github.com/ipdelete/floe/blob/55b52e731eb60d9fc4d0959edf8124b9f2c781a8/docs/engineering/parallel-tasks/threads-spike.md): overlapping import contexts broke isolation; thread-local output routing missed descriptor/child writes. Stop this path under existing contracts; no comparative thread benchmark was run. |
| Fresh file/key process workers | [#10 report](https://github.com/ipdelete/floe/blob/62c4713c6ce9a5faf8dc6be1bbffecae2da75ce4/.agents/engineering/parallel-tasks/processes-spike.md): controlled attribution and overlap, but repeated loading, fresh state and interpreter startup costs. Pool transport of loaded callables failed; a direct fork snapshot doesn't merge mutations or solve arbitrary parent thread/native state. Sampled short tasks can lose more to startup than they gain. |
| Processes with per-task groups in a delegated service | [WSL2 report](https://github.com/ipdelete/floe/blob/4752be9a983e08c0ae63de0f54fd3dba5921c3b4/.agents/engineering/parallel-tasks/dag-supervisor-spike.md): explicit, unprivileged delegation allowed killing A and its new-session leaf without killing B. On A → C and B → D, D started after B succeeded. Workflow cancellation killed both active groups. No external control interface, persisted history, installed-service crash evidence, or general performance guarantee. |
| Whole-service group only / local subreaper | Simpler for whole-run cancellation; neither process groups nor worker exit delimit A's detached children. A dedicated subreaper collected the tested orphan when alive; that's not per-task containment or protection against owner death. Still viable if selective task cancellation is deferred. |
| Stay sequential | Preserves current contracts at the cost of overlap and selective parallel cancellation. Prefer this to silently weakening cleanup or changing existing task state semantics. |

**Recommendations awaiting judgment:** (1) opt in to file-backed installed parallel mode with fresh task state; no delegation requirement for sequential runs and no implicit direct-mode fallback; (2) task-local hard cancellation vs workflow-wide cancellation, distinct from ordinary fail-fast/drain; (3) require clean descendant termination for success, with bounded drain then cleanup/failure. If any recommendation is rejected, revise the design before implementation. Exact API, protocol, retry support, cleanup bounds and #16 validation remain open.
